### Finding

**🟠 Moderate — normalization tests do not lock the stable fault category.**  
`packages/core/__tests__/normalization.test.ts:46-60, 128-158` checks that malformed normalization inputs throw `AuthorizationFault`, but never checks the stable `code` value. A regression that changes or omits the category would pass these tests. This leaves C7’s stable error-category requirement unguarded at the new public seam.

Suggested assertion:

```ts
try {
  expandRoles([], [{ roleName: "missing" }]);
  throw new Error("expected AuthorizationFault");
} catch (error) {
  expect(error).toBeInstanceOf(AuthorizationFault);
  expect((error as AuthorizationFault).code).toBe("invalid-input");
}
```

Coverage is otherwise diverse: it tests normalization results, evaluator decisions, malformed runtime inputs, type-level rejections, a built package consumer, and a packed consumer. Some effect-parity tests overlap, but they exercise grants and denials separately, so I would keep them.
